How this page was written

One command. mcp-beaver directory enumerates, connects, writes a guardfile per server, and renders this page and the guardfiles from the same record.

01

Enumerate

GET {{.Registry}}/v0/servers, unauthenticated, paginated. Keep isLatest and status: active, which drops superseded versions and dead listings for free.

02

Resolve transport

Take the first streamable-http remote. A packages-only server would have to be installed and run, so it is not listed here at all.

03

Handshake

initialize, then notifications/initialized, carrying Mcp-Session-Id forward, the way the proxy connects.

04

Introspect, with a retry

tools/list, twice if the first returns empty. One server answered 0 tools then 25 on the same session shape, so a single reading produces false negatives.

05

Read the hint, then emit

Each tool's own readOnlyHint, read off the raw JSON so absent and false stay different. A guardfile per server at scope {{.Scope}}, and this page, from the stored record.

What this does not establish

The hint is self-declared. An upstream that mislabels a tool is trusted here. Nothing in this pipeline calls a tool to find out what it does, and nothing should. A tool declaring nothing is counted as undeclared rather than guessed at from its name.

A refusal is not a verdict on a server. Requiring a token is normal and often correct. The {{.Refused}} servers above are outside the anonymous corpus, not below it.

Everything here is one reading. Surfaces change and servers go down. A directory that shows drift needs the run on a schedule and a history, and this page is one run.
