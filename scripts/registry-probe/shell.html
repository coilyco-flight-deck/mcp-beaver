The pipeline that wrote this page

Two scripts. probe.py enumerates and connects, render.py emits the HTML. The whole run takes about seven seconds.

01

Enumerate

GET registry.modelcontextprotocol.io/v0/servers, unauthenticated, paginated. Keep isLatest and status: active, which drops superseded versions and dead listings for free.

02

Resolve transport

Take the first remotes[].url. Most registry entries publish one, so nothing is installed and nothing is built.

03

Handshake

initialize, then the notifications/initialized notification, carrying Mcp-Session-Id forward. Replies arrive SSE-framed, so the parser strips data: lines rather than assuming JSON.

04

Introspect, with a retry

tools/list, twice if the first returns empty. A single reading produces false negatives: one server answered 0 tools then 25.

05

Classify and render

Each tool sorted read, mutating, or unknown from its name. Then this page and a guardfile per server, from the stored JSON.

What this does not establish

The classification is a heuristic and it was wrong first. The initial version matched tool descriptions, so "the published docs" fired the verb publish and five plain reads came back mutating. It now reads the tool name only, treats any write verb as decisive, and excludes start because get_start_path is a noun. It agrees with a hand read on the one server checked by hand, and that rule was tuned after seeing that server, so treat it as n=1.

{{NUNK}} of {{NTOOLS}} tools are unclassified and shown as such rather than guessed. Namespaced names like goji_* and skill_* carry no verb the rule recognises.

A refusal is not a verdict on a server. Requiring a token is normal and often correct. The {{NBAD}} servers above are outside the anonymous corpus, not below it.

Everything here is one reading. Surfaces change, servers go down, and three answered HTTP 503 in this run that may answer tomorrow. A real directory needs the run on a schedule and a history, which is the part that would make it a product rather than a snapshot.
